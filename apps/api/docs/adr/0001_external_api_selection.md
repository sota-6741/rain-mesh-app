# ADR-0001(api): mesh・timeseriesエンドポイントの取得戦略

## ステータス

承認済み (2026-07-02、ハイブリッド構成・擬似メッシュ方式へ再改訂)

## コンテキスト

`docs/adr/0001-external-api-selection.md` により、データソースが
「気象庁 bosai系JSON(一次) + YOLP気象情報API(補完)」のハイブリッド構成に確定した。
この2つのデータソースから、mesh(領域内の面的な雨量表示)と timeseries(地点クリック
での時系列表示)をどう構築するかを決定する必要がある。

前提となる制約:

- アメダスは点データ(全国約1,300地点、平均約17km間隔)であり、そのまま細かい
  格子に割り当てると大半のセルが空白になる
- YOLPは任意地点を取得できるが24時間5万リクエストの上限があり、全国常時取得は
  破綻する(試算: 5kmメッシュ全国分・10分毎更新で約19万リクエスト/日 → 上限の
  約4倍)
- ユーザー体験として、ズームアウト時は広域の傾向を、ズームイン時はより細かい
  粒度で雨の状況を見たい

## 決定

### mesh: 擬似メッシュ + ズームレベル連動セルサイズ + YOLPによる空白補完

- 表示領域をズームレベルに応じたセルサイズのn×n格子(擬似メッシュ)に分割する
- **ズームレベルが低いほどセルを大きく、高いほど小さくする。下限は2kmとし、
  それより細かくしない**
- セル内にアメダス観測所があれば実測値(複数なら最大値)、なければYOLPで
  解析値を補完する
- YOLPによる補完結果はセル単位・TTL10分でキャッシュし、同一領域への
  再アクセスでの追加リクエストを防ぐ
- レスポンスには実測値/解析値の由来区分を含め、FEで表示上区別する

詳細なズームレベルの定義、セルサイズ対応表、リクエスト/レスポンス仕様は
`apps/api/docs/mesh-timeseries-spec.md` を参照。

### timeseries: 近傍観測所は気象庁、それ以外はYOLP

- クリック地点の近傍にアメダス観測所があれば、気象庁の地点別時系列
  (実測値)を返す
- 近傍に観測所がなければ、YOLPで当該地点の時系列(過去実測相当+未来1時間
  予測)を返す
- いずれもBE側でキャッシュし、重複リクエストを抑制する

詳細な判定ロジック・レスポンス仕様は `apps/api/docs/mesh-timeseries-spec.md` を参照。

### 不採用にした方式(検討の記録)

| 方式                                                                    | 不採用理由                                                                       |
| ----------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| アメダス単独での擬似メッシュ                                            | 5kmメッシュで約9割が空白となり、面表示として成立しない                           |
| YOLP単独での全国メッシュ                                                | レート制限(5万件/日)を大幅に超過する                                             |
| 点データからの空間補間(ボロノイ・IDW等)                                 | 雨は局所性が強く、17km間隔の点からの補間は実際と異なる分布を見せるリスクが高い   |
| セルサイズ2km未満の詳細メッシュ                                         | データソースの解像度(YOLP解析値が約1km相当)を超えるため見せかけの精緻さになる    |
| 高解像度降水ナウキャストの非公式利用、タイル分割/最大値集約方式(旧設計) | データソース変更(気象庁bosai系+YOLP)により、旧設計の前提(250mメッシュ)自体が消滅 |

## 結果

- `app/domain/services/mesh_builder.py`: 擬似メッシュ生成・セル値割り当てを実装
- `app/domain/services/zoom_config.py`: ズームレベル→セルサイズのマッピングを保持
- `app/infrastructure/weather/jma_amedas_provider.py` / `yolp_provider.py` を実装
- `apscheduler_runner.py` を「10分毎の気象庁全国一括取得」用途で使用する
- セル単位キャッシュの実装が両エンドポイントの前提になる。この設計は旧ADR
  (250mメッシュ時代)のタイル単位キャッシュと同型であり、設計思想を再利用する
- 実測値/解析値の由来区別が、スキーマ(`rain_schema.py`)とFE表示の両方に必要になる
- 詳細仕様・未確定事項は `apps/api/docs/mesh-timeseries-spec.md` で管理する
