# ADR-0001: 雨量データの外部取得先の選定

## ステータス

承認済み (2026-07-02)

## コンテキスト

雨量メッシュを地図上に表示するには、雨量の実況データを外部から取得する必要がある。
本プロジェクトは個人開発・非商用プロジェクトであり、一般公開(不特定多数向け)ではあるが
収益化は行わない。この前提のもとで、コストとリスクのバランスが取れたデータソースを
選定する必要がある。

## 決定

気象庁「高解像度降水ナウキャスト」の非公式エンドポイントを利用する。

検討した選択肢は以下の通り。

| 選択肢                                    | 費用 | データ形式                 | リスク                                       |
| ----------------------------------------- | ---- | -------------------------- | -------------------------------------------- |
| 気象庁 非公式エンドポイント(採用)         | 無料 | タイル画像 / GRIB2(要変換) | 仕様変更・停止の可能性。利用規約の確認が必要 |
| 商用データ配信会社(ハレックス DreamAPI等) | 有料 | JSON(緯度経度指定可)       | 費用が発生するため個人開発には不釣り合い     |
| 海外の無料気象API(Open-Meteo等)           | 無料 | 地点ごとの予測値が中心     | 「面としてのメッシュ」表現に向かない可能性   |

理由:

- 商用利用ではないため、有料サービスを選ぶ必然性がない
- 面(メッシュ)としてのデータ表現に最も適している
- 個人開発であれば、非公式エンドポイントの停止・仕様変更リスクを許容できる

## 結果

- 気象庁の利用規約(著作権表示・出典明記の要否)を別途確認する必要がある
- 非公式エンドポイントである以上、過度な負荷をかけない設計が事業継続の観点で重要になる
  - BFF(Vercel)・BE(Fly.io)双方でのキャッシュ設計を必須とする(apps/api ADR-0001参照)
- `app/domain/ports/weather_provider.py` として抽象化しておくことで、
  将来的な仕様変更・停止時にも実装(`infrastructure/weather/*_provider.py`)の
  差し替えのみで対応可能な設計とする

### 未確定事項

- 緯度経度からタイル座標への変換方法
- → `apps/api/docs/data-source-investigation.md` に調査結果を随時追記する
